# Especificação: Corrupções CIFAR e Calibração de Severidade

> Responsável: autor do módulo de dados. Complementa
> `8. especificacao-drift-agent-cifar-corrompido.md`.

---

## 1. Objetivo

Criar corrupções visuais reproduzíveis para CIFAR-10 e integrá-las ao pipeline
de dados do experimento. As corrupções simulam covariate drift: alteram a
imagem `X`, mas preservam a classe `Y`.

O módulo também calibra uma severidade útil para cada corrupção antes dos
experimentos principais.

---

## 2. Corrupções Obrigatórias

Implementar diretamente sobre tensores de imagem:

1. `gaussian_noise`;
2. `gaussian_blur`;
3. `brightness_contrast`.

O resultado é inspirado em CIFAR-10-C, mas não deve alegar ser uma reprodução
do benchmark oficial.

---

## 3. Interface de Integração

Expor uma função estável, documentada e independente do experimento:

```python
def apply_corruption(
    x: torch.Tensor,
    kind: str,
    severity: int,
    seed: int | None = None,
) -> torch.Tensor:
    ...
```

Requisitos:

- entrada e saída possuem o mesmo `shape`, `dtype` e dispositivo;
- `severity` aceita somente valores inteiros de 1 a 5;
- valores de pixel permanecem na faixa esperada pelo pipeline de dados;
- a função não altera `x` in-place;
- mesma entrada, configuração e seed geram a mesma saída;
- corrupção desconhecida ou severidade inválida produz erro claro;
- os rótulos não fazem parte da função e não são alterados pelo pipeline.

O módulo pode expor helpers para corromper uma partição inteira, desde que
reutilize essa função como fonte de verdade.

---

## 4. Integração com os Dados

Integrar as corrupções para que o fluxo do agente consiga obter:

- dados limpos para o treinamento inicial;
- batches corrompidos sem rótulos para o monitoramento/detector;
- dados de treino corrompidos, distribuídos por cliente, para retreino;
- dados de teste corrompidos, separados, para avaliação e downtime.

A mesma configuração `kind`, `severity` e `seed` deve identificar um cenário.
As partições de treino e teste devem continuar separadas. Para ruído aleatório,
usar derivação de seeds reproduzível por partição/cliente sem reutilizar
necessariamente o mesmo padrão de ruído por imagem.

Não alterar a política de drift, os servidores nem a lógica de retreino; o
módulo entrega dados transformados ao fluxo definido no documento 9.

---

## 5. Calibração de Severidade

Para cada corrupção:

1. usar o modelo já treinado em CIFAR-10 limpo;
2. avaliar as severidades de 1 a 5 no conjunto de teste corrompido;
3. selecionar a menor severidade cuja acurácia fique abaixo de `0,50` e acima
   de `0,25`;
4. persistir a tabela completa e a severidade selecionada.

Se nenhuma severidade atender à faixa, registrar o resultado e exigir decisão
explícita de ajuste de parâmetros da transformação. Não escolher um nível fora
da regra silenciosamente.

O experimento principal usa apenas a severidade selecionada de cada corrupção.

---

## 6. Testes

Cobrir, no mínimo:

1. shape, dtype e dispositivo são preservados;
2. saída não compartilha mutação com a entrada;
3. pixels ficam na faixa válida;
4. seed igual reproduz a mesma corrupção;
5. seed diferente pode alterar resultados estocásticos;
6. severidades inválidas e nomes inválidos falham claramente;
7. cada tipo de corrupção altera uma imagem não degenerada;
8. severidade maior produz uma perturbação não menor segundo uma medida
   simples, como distância média à imagem original;
9. labels permanecem idênticos ao transformar uma partição `(x, y)`.

Também executar um teste leve de integração que constrói as versões limpas e
corrompidas das partições necessárias, sem iniciar treinamento federado.

---

## 7. Entregáveis

- módulo de corrupções e documentação de parâmetros;
- integração com o pipeline de dados;
- rotina/script de calibração;
- tabela de calibração versionada nos outputs do experimento;
- testes unitários e teste leve de integração;
- exemplo mínimo de uso para o responsável pelo fluxo.

---

## 8. Critério de Conclusão

Está concluído quando o responsável pelo fluxo consegue escolher uma
`corruption + severity + seed`, receber partições limpas/corrompidas
reproduzíveis e rodar a calibração sem precisar conhecer a implementação
interna das transformações.
